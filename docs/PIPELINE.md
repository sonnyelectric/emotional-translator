# Backend pipeline and adapter boundaries

A defines the in-process ports in `backend/app/audio_ai_ports.py` and owns the session, relay, clock, and alignment. B implements Scribe, model inference, the window worker, and score math. C produces the PCM frame format and consumes server events. Only the [WebSocket protocol](PROTOCOL.md) crosses the browser boundary. Treat the types and method names here as the agreement for the initial implementation.

## In-process ports

| Port or record | Contract |
|---|---|
| `PcmFrame` | Immutable `session_id: str`, `epoch: int`, `start_sample: int`, `end_sample: int`, `pcm_s16le: bytes`. Half-open bounds. The byte length equals twice the sample count. A assigns the coordinates after transport validation. |
| `ScribeAdapter` | `async open(epoch) → ScribeStream`. B exports `ElevenLabsScribeAdapter(*, api_key, vad_silence_secs)`. A passes those two settings from its backend config. B pins the approved model ID, audio format and VAD mode. Open upstream only when called. Classify setup failure as permanent or transient. |
| `ScribeStream` | `async send_pcm(pcm_s16le)`, `events() → AsyncIterator[ScribeNotice]`, `async aclose()`. B owns provider frames, message parsing and disposal. A owns concurrent reader and writer tasks, upstream origin, drains, and reconnect policy. |
| `ScribeNotice` | `epoch`, `kind=partial\|commit\|timed\|transient_error\|fatal_error`. Transcript variants carry `text`, nullable `language_code`, and an optional provider commit key if proven stable. Timed variants also carry ordered timed tokens and `timestamp_basis=connection\|segment\|unknown`. For a segment-relative clock, carry `segment_origin_samples` relative to the connection only when direct provider evidence supplies it. Error variants carry safe `code` and `message`. |
| Timed token | `text`, provider-relative integer `start_sample`, `end_sample`; convert provider time units using observed precision. B preserves order and records how units were verified. A assigns word IDs, validates text and adds the epoch origin. |
| `AudioWindow` | `session_id`, `epoch`, `start_sample`, `end_sample`, `pcm_s16le`. Same coordinate system as frames. A valid full window contains exactly 32,000 samples. |
| `WindowScheduler` | `begin_epoch(session_id, epoch, first_sample)` and `push(frame) → sequence[AudioWindow]`. B owns ring and window extraction. A calls it on accepted frames, advances epochs, and hands off ready windows without waiting for inference. |
| `ModelScorer` | Synchronous `load()` and `score(window) → ScoredWindow` on a dedicated worker. B exports `Emotion2vecLargeScorer(*, cache_dir=None)` and a separate fake in test code. Load one real model per process, only for an explicit live launch. |
| `ScoredWindow` | Window `session_id`, `epoch`, `start_sample`, `end_sample`, `score_kind=probability_like\|comparable`, and all nine `scores`. [Example window schema](../shared/schemas/v1/model-window.schema.json) maps the diagnostic shape without the in-process session ID. |
| `EmotionWorker` | B exports `BoundedEmotionWorker(scorer, *, max_pending=2)`. `async start()` loads once off the event loop and returns when ready or raises a load failure. A starts it in a process task in live mode and gates offers on readiness, leaving Scribe independent. Use nonblocking `offer(window)`, `results() → AsyncIterator[WindowNotice]`, `discard(session_id, *, epoch=None)` to drop pending work by scope, and `async aclose()` for process shutdown. |
| `WindowNotice` | Tag each settled item by session, epoch and window bounds. `kind=scored\|dropped\|silence\|failed`. Only `scored` carries a score vector. Carry monotonic enqueue/settle time and nullable start time (milliseconds) for timing-only diagnostics. A owns eligibility to update phrases and ignores quarantined completions. |
| `ScorePolicy` | B exposes pure `smooth(current, previous, config)` for same-epoch ordered windows and `classify(scores, previous_state, config)`. Classifier returns a suppressed result or a render candidate containing the enum label(s), support, intensity, opacity, and blend weight. A calls it on aggregated phrase scores and attaches word spans, identity, revisions and palette. |

A restricts the live demo to one active microphone session per process. Reject a concurrent attempt with a visible busy error. Release the live lease in cleanup. Other local clients can fetch replay. No state recovery across browser transports or process restarts.

## Clock, epochs, and fan-out

1. A counts accepted frames on the session-wide 16 kHz clock. `audio_ms = sample_offset / 16`. Paused wall time and invalid/dropped browser frames add zero samples. Keep the canonical offset monotonic across pause, resume, and Scribe reconnect.
2. Fan accepted samples to a bounded Scribe writer queue and the scheduler. Track the first sample actually forwarded on each Scribe connection and the sample range successfully sent. Use no replay of earlier microphone audio. If the queue overflows or transport loses delivery, cut the stream and establish a new epoch before forwarding more. Do not splice separated PCM under one provider-relative clock.
3. An upstream stream may be unavailable while the browser continues capture. Continue the session sample count. Start a fresh epoch and scheduler at the first frame forwarded after the reconnection. Samples with no Scribe timing cannot anchor a cloud. New Scribe connections after Pause/Resume also start fresh epochs. Never shift valid old words.
4. For connection-relative timing, use `absolute_sample = epoch_origin + relative_sample`. For validated segment-relative timing, add the explicitly observed connection-relative segment origin once. Accept words only within the sent range of that same epoch, with positive duration and ordered starts and ends. Treat unknown clock basis or an unresolvable mapping as an alignment warning and keep the stable text.
5. A serializes all outbound events through one emitter. Tag tasks and callbacks so late ones cannot change a replacement session. Pause fences new annotation updates for the epoch and freezes existing drafts. Stop permits bounded final results, then cancels and closes. Reset clears the complete session and increments its generation. Preserve observed transcript and clouds on ordinary reconnect and Stop.

## Scribe normalization and segment matching

B implements the TDD's server-only Scribe v3 Live VAD request and maps upstream provider messages to the port. Preserve the distinction between provisional text, commit, and timed commit. B checks the documented parameters, auth, actual emitted timing shape, word-item types, event order, and time basis in the opt-in smoke session. Silence and keepalive traffic are ignored. B supplies scrubbed field names, types, timing relationships and ordering examples. Do not store raw provider or participant audio in the repo.

A emits stable text when a commit arrives. Maintain pending timestamp associations per upstream epoch. Prefer a proven provider key. Otherwise use validated FIFO order plus exact or NFC and whitespace-normalized text matching. If repeated identical phrases lack a reliable ordering or key, preserve each genuine commit and mark unresolvable timings without guessing. Deduplicate by upstream identity when available, or by proven duplicate placement in the event lifecycle. Do not use identical text alone as a deduplication key. Keep delayed timed events independent of newer partial text and do not emit a second append. Provider auth, quota, and terms failures are permanent. Network close, provider transient/server errors and rate limits attempt bounded backoff with jitter. Clear stale partial text on epoch loss. Preserve committed words.

## Windowing and backpressure

- B's ring holds at least eight seconds of PCM and is bounded. At the origin of each epoch, the first ready window is `[origin, origin + 32000)`. Each next start increments by 16,000. Never pad a short tail or join windows across epochs. Reinitialize smoothing after an epoch change or a gap larger than one hop.
- The worker may settle mostly silent windows without inference using an inexpensive deterministic energy check. B records the threshold and uses it only as a silence gate. Configure at most two pending windows by default, separate from the running item. If full, evict the oldest not-yet-started item, report the drop, and admit the new one. Kind `failed` covers model/load or unsupported score errors. A reports a small degradation warning and keeps Scribe running.
- Keep the model process-local and use a bounded dedicated executor or worker. Keep model I/O and synchronous inference away from the event loop. Cancel pending work when sessions change. If the underlying call cannot be interrupted, quarantine completion via its tags and avoid starting a concurrent instance. Report dropped windows, queue wait, inference time, and stale results without content logs.
- Use `iic/emotion2vec_plus_large` (TDD's FunASR reference for emotion2vec+ Large), 16 kHz input, utterance granularity, and embeddings off. Inspect the real call output. Pin the library combination after a successful target-laptop run. Accept proven class aliases only and map them to the nine labels. Label-only, incomplete, negative, unknown-layout or non-finite output fails explicitly. Document the transform and record `score_kind` for actual vectors. Never turn embeddings or unverified values into scores.

## Scores and visual classification

1. For probability-like valid outputs, normalize to a sum of one and check tolerance 1e-3. For proven comparable outputs document the bounded [0,1] conversion and do not require a unit sum. Treat all scores as relative model support. Smooth each score with an EMA of alpha 0.55 over ordered consecutive windows. Keep previous vectors per session and epoch. Probability-like vectors remain normalized.
2. Suppress when neutral, other, or unknown leads or ties for the lead. Also let the configurable neutral threshold veto visible classification if reached. With eligible non-neutral evidence, 0.25 starts faint coverage and 0.42 starts standard coverage. Use a 0.06 hysteresis band for exiting the previous support tier. Neutral and unsupported categories bypass hysteresis. Resolve ties between visible categories deterministically in schema label order.
3. Blend only when the top two categories from all nine are visible, the primary meets standard entry support, the secondary is at least 0.30, and the gap is at most 0.15. Secondary weight is `secondary / (primary + secondary)`. Use at most two categories.
4. Start with intensity `clip((p - max(other scores) + 0.25) / 0.75, 0, 1)`. Map support monotonically over the nominal faint range 0.14–0.30 and standard range 0.35–0.75 with clamping. Use support breakpoints for opacity even within hysteresis. Size multiplier starts at `1 + 0.25 * visual_intensity`. Bound saturation and preserve text contrast. Tune with the demo scenario matrix and record actual configuration. [Template](../.env.example) · [Acceptance](ACCEPTANCE.md#g5--resilience-and-target-hardware)

## Alignment, revision, and finalization

A indexes valid scored windows by sample interval and short-lived epoch until timed words arrive. Retain them through pending timestamp association and prune with bounded age/size. On a timed word, weight each overlapping score vector by interval overlap divided by word duration and a recency factor. For the initial policy use `1 - 0.25 * min(2, abs(window_midpoint_ms - word_midpoint_ms) / 1000)`. Give unusable windows zero weight. Normalize by total usable weight once per word and aggregate neighboring covered words once per word. A word or span with no temporal evidence stays plain. Either arrival order, model-first or timestamp-first, must produce the same eligible anchors when their inputs match.

Group contiguous words by punctuation, pauses over 350 ms, and sustained change in eligible dominant vocal cue. Start with at least two adjacent words supporting an emotion change before a split unless punctuation or a pause already provides a boundary. Prefer coherent phrases to single-word clouds. Take grouping decisions before an annotation ID first becomes visible. Keep emitted IDs and anchors stable as later windows revise scores, color or intensity. Retract if the draft loses eligibility. Expose the last defensible geometry until updated, retracted, or frozen. C uses the timed word IDs to group visual line runs.

A finalizes each phrase once every eligible overlapping window has settled and the scheduler has passed the last relevant hop, or a bounded deadline is reached. Start with 2 s of captured-audio lookahead after the last word. Add a bounded pending-work wall timeout so no draft waits forever when timestamps or audio stop. The Stop drain is capped independently at 1,200 ms. Freeze the best supported visible or hidden state, emit no cloud if there has never been valid evidence, and count discarded late results. Communicate that a 2-second window yields a phrase-level cue and exact word causation is unverified.

## Measurements

C records the cumulative sample endpoint and its estimated browser monotonic capture time at frame emission, and the first actually rendered cloud time after layout in an opt-in local debug run. A records elapsed milestones for accepted samples, partial/commit/timed, model enqueue/start/finish, event serialization and drops. Match by session, epoch and interval. Estimate phrase-end in the browser clock by interpolation around the matching sample endpoint. State capture, timestamp and paint approximation limits. Report p50/p95 for mic-to-partial, phrase-end-to-timed, inference queue wait and run time, and phrase-end-to-first-cloud. Report counts, hardware, long-speech VAD behavior and any missed ~3 s target.
